# ボード上下スペーシング不具合修正 要求仕様書

## 1. 現状の問題

### 1.1 不具合概要

スペーシングオプションを0pxに設定しても、CPU手持ち駒エリアとボード間、およびボードとプレイヤー手持ち駒エリア間に**約40〜60pxの余白**が発生する。

### 1.2 原因分析

現在のレイアウト構造において、ボードを囲むラッパー要素が `flex: '1'` を持ち、残りの垂直スペースを全て吸収している。

```
親コンテナ (gap: 6px, height: 100dvh)
├── Header (flex: 'none')
├── CPU StackArea wrapper (flex: 'none', marginBottom: topSpacing - 6)
├── ボードラッパー (flex: '1') ← 問題箇所
│   └── ボード本体 (alignItems/justifyContent: 'center')
├── Player StackArea wrapper (flex: 'none', marginTop: bottomSpacing - 6)
├── MessageBar (flex: 'none')
└── Buttons (flex: 'none')
```

**問題のメカニズム:**

1. `flex: '1'` により、ボードラッパーが画面の残りスペースを全て占有
2. ボード本体はラッパー内で中央配置（`alignItems: 'center'`）
3. `(ラッパー高さ - ボード高さ) / 2` の余白が上下に発生
4. marginによるgap調整はラッパー外部のみに作用し、内部余白は消えない

### 1.3 影響範囲

- 全ての画面サイズで発生
- スペーシング設定値に関わらず、最低40〜60pxの余白が常に存在
- ユーザーが0pxを選択しても意図した「密着」状態にならない

## 2. 要求仕様

### 2.1 機能要件

#### FR-001: 0px設定時の完全密着

| 項目 | 内容 |
|------|------|
| 要件ID | FR-001 |
| 優先度 | 高 |
| 説明 | スペーシング値を0pxに設定した場合、CPU手持ち駒エリアとボード、ボードとプレイヤー手持ち駒エリアが完全に密着すること（余白0px） |
| 受入条件 | 0px設定時、要素間の視覚的な隙間が存在しないこと |

#### FR-002: スペーシング値の正確な反映

| 項目 | 内容 |
|------|------|
| 要件ID | FR-002 |
| 優先度 | 高 |
| 説明 | 設定したスペーシング値（0〜40px）が、実際の要素間距離として正確に反映されること |
| 受入条件 | 設定値Npxのとき、実測値がN±1px以内であること |

#### FR-003: 上下スペーシングの独立制御

| 項目 | 内容 |
|------|------|
| 要件ID | FR-003 |
| 優先度 | 中 |
| 説明 | 上部スペース（CPU↔Board）と下部スペース（Board↔YOU）を独立して設定できること |
| 受入条件 | 一方の変更が他方に影響しないこと |

#### NFR-002: 既存機能への影響なし

| 項目 | 内容 |

## 3. 設計方針

### 3.1 解決アプローチ

ボードラッパーの `flex: '1'` を削除し、ボードを固定サイズ要素として扱う。

#### 変更前
```
ボードラッパー: flex: '1' (可変、残りスペース全取得)
  └── ボード: 中央配置 (内部に余白発生)
```

#### 変更後
```
ボードラッパー: flex: 'none' (固定、ボードサイズに合致)
  └── ボード: そのまま配置 (余白なし)
```

### 3.2 レイアウト構造（修正後）

```
親コンテナ (flexDirection: 'column', alignItems: 'center')
├── Header (flex: 'none')
├── CPU StackArea (flex: 'none')
├── 上部スペーサー (height: topSpacing) ※0pxなら非表示
├── ボード (flex: 'none') ← 固定サイズ
├── 下部スペーサー (height: bottomSpacing) ※0pxなら非表示
├── Player StackArea (flex: 'none')
├── MessageBar (flex: 'none')
└── Buttons (flex: 'none')
```

### 3.3 スペーシング制御方式

| 方式 | 説明 |
|------|------|
| **推奨: スペーサー要素方式** | 専用のdiv要素でスペースを確保。0pxのときは要素自体を非表示 |
| 代替: margin方式 | 親のgapを削除し、各要素にmarginを直接設定 |

### 3.4 親コンテナのgap処理

現在の `gap: '6px'` は以下のいずれかで対応:

1. **gapを削除** → 全要素間をスペーサーまたはmarginで個別制御
2. **gapを維持** → CPU↔Board、Board↔YOU間のみスペーサーで上書き

## 6. 参考

### 現在の問題を示す計算例

**画面高さ700pxの場合:**

```
固定要素合計: ~276px
ボード本体: ~317px
ボードラッパー(flex:1): 700 - 276 = 424px
内部余白: (424 - 317) / 2 = 約53px（上下各）
```

→ 0px設定でも**約53pxの余白**が発生
